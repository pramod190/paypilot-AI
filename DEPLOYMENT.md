# PayPilot AI - Production Deployment Guide

PayPilot AI is architected as a full-stack monorepo (`packages/shared`, `apps/api`, `apps/web`). In production, the backend Express server serves both the **REST API endpoints** (`/api/...`) and the **production-built React frontend** (`apps/web/dist`) on a single port. This removes cross-origin (CORS) complexity, simplifies SSL, and reduces hosting costs.

---

## 📋 Pre-Deployment Checklist

Before deploying, ensure you have:
1. **GitHub Repository**: Push your code to a GitHub repository (instructions below).
2. **PostgreSQL Database**: Either managed (Render, Supabase, Neon, Railway) or self-hosted.
3. **PayPal Developer Credentials**:
   - `PAYPAL_CLIENT_ID` & `PAYPAL_CLIENT_SECRET` (from [developer.paypal.com](https://developer.paypal.com/dashboard/applications/sandbox)).
   - `PAYPAL_ENVIRONMENT=sandbox` (or `production`).
4. **AI API Key**:
   - `GEMINI_API_KEY` (from [Google AI Studio](https://aistudio.google.com/)) or `OPENAI_API_KEY`.
5. **A Secure Secret for JWT**:
   - Any long, random string for `JWT_SECRET`.

## 🚀 Option 1: Render (Recommended — Easiest 1-Click Setup)

Render is pre-configured via the included [`render.yaml`](./render.yaml) blueprint, which provisions both the web service and a free PostgreSQL database.

### Step-by-Step Instructions:

1. **Push your code to GitHub**:
   ```bash
   git init
   git add .
   git commit -m "feat: PayPilot AI deployment ready"
   git branch -M main
   git remote add origin https://github.com/<your-username>/paypilot-ai.git
   git push -u origin main
   ```

2. **Deploy Blueprint on Render**:
   - Log into [Render Dashboard](https://dashboard.render.com).
   - Click **New +** in the top right, then select **Blueprint**.
   - Connect your GitHub repository `paypilot-ai`.
   - Render will detect `render.yaml` and create:
     - **Database**: `paypilot-db` (PostgreSQL)
     - **Web Service**: `paypilot-ai` (Node.js)

3. **Fill in Environment Secrets in Render**:
   In the Render Web Service Settings -> **Environment**, fill in the following:
   - `DATABASE_URL`: *(Auto-linked by Render)*
   - `JWT_SECRET`: *(Auto-generated by Render)*
   - `PAYPAL_CLIENT_ID`: Your PayPal Sandbox Client ID
   - `PAYPAL_CLIENT_SECRET`: Your PayPal Sandbox Secret
   - `PAYPAL_ENVIRONMENT`: `sandbox`
   - `GEMINI_API_KEY`: Your Google Gemini API Key
   - `CLIENT_URL`: `https://<your-render-subdomain>.onrender.com`
   - `PAYPAL_RETURN_URL`: `https://<your-render-subdomain>.onrender.com/payment/success`
   - `PAYPAL_CANCEL_URL`: `https://<your-render-subdomain>.onrender.com/payment/cancel`

4. Click **Apply Changes** / **Manual Deploy**.
   - Render runs `npm ci && npm run build`
   - Runs `npm run db:migrate` (Prisma migrations)
   - Starts the server with `npm start`
   - Access your live app at `https://<your-render-subdomain>.onrender.com`!

## 🚂 Option 2: Railway

Railway offers native PostgreSQL support and automatically builds the multi-stage Dockerfile.

### Step-by-Step Instructions:

1. Go to [railway.app](https://railway.app) and click **New Project** -> **Deploy from GitHub repo**.
2. Select your `paypilot-ai` repository.
3. Click **Add a Service** -> **Database** -> **PostgreSQL**.
4. In your Web Service settings, add the environment variables:
   - `DATABASE_URL`: `${{Postgres.DATABASE_URL}}` *(Railway variable reference)*
   - `NODE_ENV`: `production`
   - `PORT`: `4000`
   - `JWT_SECRET`: `super-secret-random-jwt-key-64chars`
   - `PAYPAL_CLIENT_ID`: `your_sandbox_client_id`
   - `PAYPAL_CLIENT_SECRET`: `your_sandbox_client_secret`
   - `PAYPAL_ENVIRONMENT`: `sandbox`
   - `GEMINI_API_KEY`: `your_gemini_api_key`
   - `CLIENT_URL`: `https://${{RAILWAY_PUBLIC_DOMAIN}}`
   - `PAYPAL_RETURN_URL`: `https://${{RAILWAY_PUBLIC_DOMAIN}}/payment/success`
   - `PAYPAL_CANCEL_URL`: `https://${{RAILWAY_PUBLIC_DOMAIN}}/payment/cancel`
5. Railway will automatically detect the [`Dockerfile`](./Dockerfile), build it in stages, run migrations, and launch your service.

## 🐳 Option 3: Docker (Self-Hosted / VPS / AWS EC2 / DigitalOcean)

You can containerize and run PayPilot anywhere Docker is installed.

### 1. Build the Docker Image:
```bash
docker build -t paypilot-ai:latest .
```

### 2. Run with Docker:
```bash
docker run -d \
  --name paypilot-app \
  -p 4000:4000 \
  -e NODE_ENV=production \
  -e PORT=4000 \
  -e DATABASE_URL="postgresql://user:password@host:5432/paypilot?sslmode=require" \
  -e JWT_SECRET="your-production-jwt-secret" \
  -e PAYPAL_CLIENT_ID="your_paypal_client_id" \
  -e PAYPAL_CLIENT_SECRET="your_paypal_client_secret" \
  -e PAYPAL_ENVIRONMENT="sandbox" \
  -e GEMINI_API_KEY="your_gemini_api_key" \
  -e CLIENT_URL="https://yourdomain.com" \
  -e PAYPAL_RETURN_URL="https://yourdomain.com/payment/success" \
  -e PAYPAL_CANCEL_URL="https://yourdomain.com/payment/cancel" \
  paypilot-ai:latest
```

## 🔑 Production Environment Variables Reference

| Variable | Description | Required? | Example |
| :--- | :--- | :---: | :--- |
| `NODE_ENV` | Application environment | Yes | `production` |
| `PORT` | Listening port for the combined service | Yes | `4000` |
| `DATABASE_URL` | PostgreSQL connection string | Yes | `postgresql://...` |
| `JWT_SECRET` | Secret key used to sign JWT auth tokens | Yes | `32+ random characters` |
| `PAYPAL_CLIENT_ID` | PayPal REST API app Client ID | Yes | `A...` |
| `PAYPAL_CLIENT_SECRET` | PayPal REST API app Secret | Yes | `E...` |
| `PAYPAL_ENVIRONMENT` | PayPal environment | Yes | `sandbox` or `live` |
| `GEMINI_API_KEY` | Google Gemini API key for copilot intelligence | Recommended | `AIza...` |
| `CLIENT_URL` | Base public URL of your deployed application | Yes | `https://yourdomain.com` |
| `PAYPAL_RETURN_URL` | PayPal redirect target on approval | Yes | `https://yourdomain.com/payment/success` |
| `PAYPAL_CANCEL_URL` | PayPal redirect target on cancellation | Yes | `https://yourdomain.com/payment/cancel` |
| `DEMO_LOGIN_ENABLED` | Allows fallback demo login identity if needed | Optional | `false` (recommended for prod) |
